# Sprint 04 review — codegen engine (Android)

**Goal:** turn `appconfig.json` into a complete, buildable Gradle project —
deterministically, reproducibly, and with golden-file tests that make template
changes visible.

**The constraint that governs everything:** identical input must produce
byte-identical output. Without it the three-way cache key (ADR 0004) never hits,
every user-triggered build is a full recompile, and the unit economics in master
spec §16 do not hold.

## What shipped

### The shell is its own template

`shells/android` is one directory that is simultaneously the app Android Studio
opens and the tree the generator renders. Files under `templates/` are rendered
with Scriban; everything else is copied verbatim. The committed concrete file
for each template is _the rendering of that template against the shell's own
`appconfig.json`_, regenerated by `tools/ApproveGolden` and asserted by
`ShellTemplateTests`.

The sprint plan rates template drift as the highest-likelihood risk, and it is
right: a forked template looks correct for about a sprint, then starts failing
for customers on code that works perfectly here. One directory is the answer,
and the test that asserts the shell equals its own rendering is what makes a
fork fail loudly. Recorded as [ADR 0006](docs/adr/0006-codegen-architecture.md).

### Escaping is a property of the model, not the call site

`TemplateModel` hands templates an object whose every string is _already_
escaped for the file being written. A template author writes `{{ app.name }}`
and cannot get it wrong, because there is no unescaped value to reach for.

The obvious alternative — `{{ android_string app.name }}` — works exactly as
long as everyone remembers, and the failure when someone forgets is invisible:
the project generates, the golden file records the wrong bytes, and the build
breaks only for customers whose app name contains an apostrophe. A template with
no registered escaping rule is a hard error rather than a silent fall back to
none.

`edge-hostile-text.json` exists to prove it: an app name of
`@Bob's "Diner" & Grill <$5`. It reaches a compiled APK whose `application-label`
reads back byte for byte, through XML entities, aapt2's backslash rules, and
binary resource encoding.

## Three bugs, and which mechanism caught each

This is the sprint's most useful result, because it says what each layer of
testing is actually worth.

**1. `JsonValue` read only in its parsed form** — caught by a _unit test_.
`GetValue<JsonElement>()` works only for nodes parsed from text. Every fixture
comes from a file, so every test passed; the first config assembled in memory
would have thrown, which is what the API will do for every real customer. The
Sprint 01 canonicaliser already handled both forms and said why in a comment —
the lesson is that a hard-won note in one file does not protect the next one.

**2. `namespace` taken from the customer's bundle id** — caught by a _real
Gradle build_, and by nothing else. `R` and `BuildConfig` were generated into
`com.acme.whatever` while the shell's Kotlin sources still imported
`dev.shellwright.shell.R`. Every generated project failed to compile. All 71
unit tests passed. Every golden file matched — because a snapshot records what
the generator produced, not whether Gradle accepts it.

**3. A fixed orientation trips two lint checks, not one** — caught by _building
a project no fixture described_. `DiscouragedApi` objects to
`android:screenOrientation` existing at all; `LockedOrientationActivity` objects
to its value. Suppressing only the first still fails the build, and lint runs
with warnings as errors in every generated project. No fixture set an
orientation, so nothing tested it.

The pattern is hard to miss:

| Mechanism        | Catches                                   | Cannot catch                |
| ---------------- | ----------------------------------------- | --------------------------- |
| Unit tests       | Escaping, sorting, cache-key behaviour    | Whether the output compiles |
| Golden snapshots | Any change to generated bytes, reviewably | Whether the output compiles |
| Real build       | Whether the output compiles               | Anything with no fixture    |

⚠️ Bugs 2 and 3 were both found by running Gradle, not by reading a diff. That
is the argument for `generated-android-builds` in `nightly.yml` being a required
job rather than a nice-to-have, and for the corpus growing every time a bug like
3 appears. Both new fixtures — `edge-hostile-text` and `edge-portrait-locked` —
were added because of a specific failure, not in anticipation of one.

## Decisions worth recording

- **Templates live under `templates/`, not beside their output.** Not tidiness:
  the Android resource merger rejects any file under `res/` whose name does not
  end in `.xml`, so a `colors.xml.tmpl` beside `colors.xml` breaks the shell's
  own build. Renaming to `colors.tmpl.xml` is worse — the merger then parses it
  as a real resource and collides with the file it generates.
- **A duplicate output path is an error, not a last-write-wins overwrite.** It
  caught the shell's own `appconfig.json` being both copied and generated on the
  generator's first ever run.
- **The generation manifest carries no timestamp.** A `generatedAt` field would
  make every project differ from every other and destroy byte-identity. The
  build record knows the time already.
- **The corpus is seven fixtures, not twenty-nine.** The sprint plan rates
  "snapshots become noise nobody reads" as high-likelihood, and a snapshot review
  nobody performs is worse than none because it looks like review.

## Not in scope, deliberately

No iOS generation — that is Sprint 05, and it shares the sink, the manifest, the
determinism rules and the golden infrastructure built here. No plugin dependency
blocks; the templates leave the seam and Sprint 10 fills it.
